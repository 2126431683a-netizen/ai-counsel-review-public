# AI审稿团 v11.2 详细教程
Git源宝审稿室 · 从安装到读懂每一条意见

[本次发布与下载](https://github.com/vashzwingli/ai-counsel-review/releases/tag/review-v11.2)

## 1. 先跑通一次完整审稿

这是运行在自己电脑上的审稿工作台。网页和EXE使用同一套界面：五个评审团先看稿，主编最后汇总。安装本程序不需要注册账号或登录密码；使用模型仍需连接本地服务或配置自己的API。

| 版本标识 | 含义 |
| --- | --- |
| 发布版 v11.2 | 本次网页、墨镜猫图标、安装包和教程 |
| 评分规则 v11 | 五团评分、人设与开头/商业融合规则 |
| 完播模型 manuscript-review-v1 | 自动稿面启发式推算，未用真实账号数据校准 |
| 上游 0.14.1 | The AI Counsel 的基础版本 |

1. 双击v11.2安装包，安装完成后打开AI审稿团，点击“启动并打开”。浏览器会进入 http://127.0.0.1:3340/。
2. 首次使用先连接模型。没有模型时，展开“模型连接与高级配置”；已有配置时，可在右侧“本次审阅安排”点“调整”。
3. 粘贴一篇完整稿件，先用默认五团与1轮快审。确认模型和主编后点“开始审稿”，等各团返回和主编收束。
4. 先看主编结论和右上角红色分数，再点完播曲线节点查看原文依据。最后按需要查看各团评论和完整报告。

> 看见评分规则v11或上游0.14.1，不表示安装包没有更新。以启动器v11.2和本次发布说明为准。

## 2. 安装、更新与停止服务

安装包适用于Windows x64，内置运行环境，无需额外安装Python或Node.js。程序不附带大模型权重、API密钥和个人审稿记录。

| 位置 | 用途 |
| --- | --- |
| 程序目录 | EXE、网页资源、角色说明、许可证与详细教程 |
| 独立数据目录 | 模型设置、密钥、人设、历史和日志 |
| http://127.0.0.1:3340/ | 本机工作台地址，不是互联网公开网站 |

1. 新装：选择空的独立程序目录，默认在 %LOCALAPPDATA%\Programs\AICounselReview。不要选放有其他文件的普通文件夹。
2. 升级：先在原启动器点“停止本机服务”，再关闭原启动器；运行v11.2安装包，选择原程序目录进行更新。程序会拒绝覆盖仍在运行的安装版服务。
3. 升级前备份数据目录 %LOCALAPPDATA%\AICounselReview。用资源管理器地址栏粘贴该路径，即可找到设置、人设、记录和凭据。备份放在自己可信的位置。
4. 安装完成后点“启动并打开”。如果仍看到旧界面，确认旧服务已停止，再刷新浏览器并重新打开记录。
5. 退出时先保存需要的内容，再点启动器“停止本机服务”。只关闭网页或启动器窗口，不等于已停止后台服务。

> 源码网页版与安装版默认共用3340端口。先停止当前所属的服务，再启动另一种版本；不要同时运行。安装升级保留已有配置，不会强制覆盖你改过的人设。

## 3. 最简单地接入本地模型

这里连接已经运行的模型服务，不会替你下载模型。先在Ollama或LM Studio中准备聊天模型，再回到审稿工作台。模型名称以检测结果为准，不要照抄其他人的型号。

| 服务 | 本程序预填地址 |
| --- | --- |
| Ollama | http://127.0.0.1:11434 |
| LM Studio | http://127.0.0.1:1234/v1 |
| 其他本机OpenAI兼容服务 | 填写它实际提供的基础地址 |

1. Ollama：从官方来源安装，打开软件并下载一个适合电脑的聊天模型。确认模型服务在运行；默认API端口为11434。
2. LM Studio：下载聊天模型，在Developer/本地服务页面加载模型并启动服务。常见端口为1234；若改过端口，以软件实际显示为准。
3. 在审稿工作台展开“模型连接与高级配置”或打开“模型与 API 设置”，找到“连接本地模型”。选择Ollama、LM Studio或其他本地API。
4. 点“检测本地模型”，从“选择聊天模型”中选择实际返回的模型，再点“用这个模型审稿”。单纯检测不会切换当前模型。
5. 只有地址不同或服务启用了访问密钥时，才展开“修改地址或填写密钥”。启用了访问保护就填写对应令牌，未启用可留空。

> 检测成功只说明模型列表可访问。长稿审阅还依赖上下文长度、模型指令遵循能力和电脑性能；第一次生成可能需要加载模型。本地连接单独保存，不覆盖已有云端自定义API。局域网或远程服务请走自定义API入口。

## 4. 接入自己的API

自定义API入口用于兼容OpenAI聊天接口的服务。准备三项信息：服务基础地址、实际模型ID、访问密钥。密钥由你在本机界面填写，不需要发给任何人。

| 现象 | 优先核对 |
| --- | --- |
| 返回网页或HTML | API地址是否误填成官网/控制台 |
| 401或403 | 密钥、授权范围与服务账号状态 |
| 模型不可用 | 实际模型ID、权限与余额/配额 |
| 连接意外关闭 | 上游服务、网关超时、并发限制及模型加载 |

1. 打开左下“模型与 API 设置”，进入“模型与 API 设置”分类，找到自定义端点相关配置。填写便于自己识别的名称。
2. 基础地址填写服务商提供的API地址，例如 https://api.example.com/v1。不要填产品官网、登录页或控制台地址；通常不要追加完整的 /chat/completions 路径。
3. 按服务要求填密钥并测试。确认启用该来源，返回开始页选择对应自定义模型。若列表不能加载，先核对地址、鉴权和服务是否提供模型列表。
4. 模型ID必须是服务实际支持的标识。平台展示名和API调用ID可能不同；不要因为界面能选中，就假定上游支持调用。
5. 先用一篇短的完整稿件和1轮审阅试运行。确认各团能正常返回评论、分项依据和主编结论，再增加篇幅或轮数。

> 连接云端API时，审稿正文和评审上下文会发送到你选择的服务；本地模型则由你本机的服务处理。不要用安装包或GitHub仓库存放个人密钥。

## 5. 准备稿件与安排评审

先给出完整稿件，让评审团能回查前后解释。文章、报告、小说和口播稿都可以讨论；当前开头15–20秒与完播曲线主要面向视频/口播稿。对非视频文本，口播时间与完播预估只作阅读节奏参考。

1. 在“放入稿件”中粘贴正文。必要的目标说明可用“备注：”开头，简要说明受众、用途、审阅重点、合作属性和暂未拍摄的部分。
2. 点“附加”可上传PDF、TXT、MD等支持的文件。检查提取预览与截断提示；扫描PDF未必能准确识别。Word文稿请先复制正文或转成PDF/TXT，当前上传入口不支持DOCX。
3. 保留段落和标题。口播以外的镜头、音效等备注明确写“画面：”“镜头：”“备注：”，有助于区分正文与制作提示；这也会影响粗估时间是否接近实际。
4. 确认右侧当前模型、参与评审的五团和主编。首次建议1轮快审；需要交叉复核可用2轮。更多轮是继续审同一份稿件，不会自动把原稿改得更好。
5. 提交前确认模型已经选择。“开始审稿”不可点时，检查正文、角色数量、主编和模型是否齐全。输入框中的Enter可能触发提交，换行请用Shift+Enter。

> 轮数是各团审阅次数，主编最后汇总一次。五团×轮数之外，还可能有整理、复核和失败重试调用；多轮会增加等待与费用。当前界面可选1至10轮。

## 6. 读懂主编、评审团和分数

结果区先给主编结论，右上角用红笔样式显示最终有效综合稿面分。这个分数沿用十分制，由程序按已校验分项和固定权重计算，不是完播率，也不是主编随口给出的另一套总分。

| 评审团 | 主要关心 | 综合侧重 |
| --- | --- | --- |
| 实用团 | 投入、门槛、实际价值 | 30% |
| 技术团 | 准确性、实测与边界 | 25% |
| 新手团 | 理解与动手路径 | 20% |
| 表达趣味团 | 表达、节奏与期待 | 15% |
| 观点思考团 | 论证、局限与意义 | 10% |

1. 先看主编判断与关注点，明确哪些值得保留、哪些影响目标达成。关注点按需展开，完整意见可复制。
2. 点“主编完整意见”查看章节导航、三轴分析、原始维度和主编对各团意见的取舍。各轮评分变化只是复核记录，不等于稿件质量在提升。
3. 点击各团卡片筛选评论，再点一条评论查看对应原文、相关解释、判断摘要和子项分数。不同画像可以持不同意见。
4. 点“各团评分与侧重”看格子权重和分项。团内一般为内容60%、开头15%、商业融合25%；无商业推广时商业不适用，内容/开头归一为80%/20%。
5. 遇到缺分先看原因。完整且可核对的评分明细可以恢复格式异常的汇总，但系统不会猜分、把缺分当零或偷偷提高其他团权重。

> 引文能定位只说明出处匹配，不代表模型判断一定正确。圆桌气泡是审阅关注点和返回评论的展示，不是模型实时内部思考。主编和作者仍需结合全文复核意见。

## 7. 使用自动完播曲线

无需填写任何留存参数。系统读取这份稿件的正文段落，以及各团已有的有效分项和可定位引文，自动生成分段曲线。有足够依据的旧记录也能直接展示，不需要再调用模型。

1. 看“稿面预估完播”及旁边的敏感性范围。横轴是按可识别口播粗估的时间，纵轴是持续观看比例；不是平台后台实测数据。
2. 点击“前15秒”“前20秒”可快速查看开头。点击曲线任一段或用“查看节点”下拉选择，下面的依据面板会同步切换。键盘也可聚焦节点按Enter选择。
3. 在依据面板切换“开头留人”“段落衔接”“商业融合”。查看节点对应原稿，展开前后段，检查该团是否漏看了后文解释。
4. 右侧明确标注“直接对应本段”或“各团全文评价参考”，并展示原始引文、理由和全文相关解释。未定位到本段证据时，不会谎称该团已经逐段指出这里有问题。
5. 红点表示商业相关段。商业融合评价越高，额外流失影响越小；品牌名本身不算广告，无商业适用项不增加商业流失。相同问题不会因多团重复提到而累加惩罚。

> 当前为未校准的启发式稿面预估，使用公开规则与语速假设，不是基于真实账号留存训练的预测。浅蓝带是敏感性范围，不是统计置信区间。关键依据不足会提示原因、不显示百分比。成片表演、剪辑、标题封面和流量来源仍会改变结果；点“这条曲线如何得出”可查具体口径。

## 8. 导入、修改和管理人设

展开开始页“评审团与主编”，可管理角色卡片。默认保留五个审稿团与独立主编；角色画像影响评论视角，图标只是识别方式，不会改变评分规则。

| MD文件示例结构 | 建议内容 |
| --- | --- |
| # 段落逻辑评审团 | 清楚、唯一的角色名 |
| 职责 | 检查主题推进、承接、因果与前后解释 |
| 审阅规则 | 先通读全文，再给带原文依据的判断 |
| 输出要求 | 观众评论在前；依据、限定和建议在详情 |

1. 点“选择人设文件”或把文件拖入导入区，支持MD、TXT、JSON，可一次添加多个。角色文件只导入人设内容，不导入其中的模型连接和密钥设置。
2. 导入后检查角色名称、职责、系统提示词与是否勾选参与。卡片编辑按钮可以修改人设；主编通过“编辑主编设定”单独修改。
3. 人设应要求通读全文，先核对前后解释，再判断问题；意见要引用原文、区分事实/推断/待确认，不能为了显得严格而凑问题。
4. 添加新团不会自动变成内置评分组。普通自定义角色可能能给评论，却没有受支持的分项配置；改变内置五团组合也可能无法形成原来的固定加权总分。
5. 同名角色可能被跳过。希望更新已有角色时，先备份，再打开原卡片修改或明确处理旧角色；不要把“导入成功”当作已覆盖原人设。

> 当前支持2至8个参与团和单独一位主编。想保留原五团综合分时，先保留默认组合，用自定义角色作补充讨论；权重不是换个名字就会自动改变。

## 9. 排查常见问题与备份

先确认是模型连接、数据格式还是页面显示的问题，再处理。不要为了解决一次返回失败而直接清空数据目录。

| 遇到的问题 | 怎么处理 |
| --- | --- |
| 网页打不开 | 先启动程序；检查原服务是否占用3340，再从对应启动器停止后重开 |
| 检测不到本地模型 | 确认模型软件已运行、模型已下载、服务已开启，检查端口和可选密钥 |
| 服务突然断开或超时 | 查看上游与本地模型日志；用短的完整稿件、1轮排查，检查模型能力与服务并发额度 |
| 评论有了但评分没有 | 打开该团详情看缺失/冲突/引文原因；模型输出不完整时不会硬凑总分 |
| 没有完播曲线 | 该记录可能缺少开头、衔接或商业适用性等关键有效依据；不是所有旧记录都能推算 |
| 页面仍是旧外观 | 确认启动的是新版服务；停止旧服务，刷新页面并重新打开历史 |
| 换电脑记录不见了 | 程序与数据分开；停止两边服务后复制独立数据目录，凭据能否直接使用取决于保存方式 |

1. 启动器点“打开数据目录”，停止服务后复制整份数据目录作备份。也可使用设置里的“备份与重置”查看可用备份功能。
2. 使用操作系统凭据保存区时，密钥不一定随普通文件备份迁移；到新电脑可能需要重新填写。不要把备份发到公开仓库。
3. server.log和launcher-error.log有助于定位启动问题。分享日志前先检查并遮盖密钥、私有接口和稿件。
4. 卸载默认保留独立数据；彻底清除个人记录应由自己确认后单独处理。更新时不要用卸载代替备份。

> 本地服务只监听127.0.0.1。手机或其他电脑不能直接用你的127.0.0.1访问它；GitHub上传源码也不会自动产生公网可用的网站。

普通使用者直接安装EXE即可；这一页供需要从GitHub运行或核验下载文件的人。仓库和Release目前保留原有私有权限，访问需要对应GitHub账号的授权。

| 参考 | 地址 |
| --- | --- |
| 本次发布与下载 | https://github.com/vashzwingli/ai-counsel-review/releases/tag/review-v11.2 |
| 中文项目源码 | https://github.com/vashzwingli/ai-counsel-review |
| Ollama Windows说明 | https://docs.ollama.com/windows |
| LM Studio本地服务 | https://lmstudio.ai/docs/developer/core/server |
| 上游项目与MIT许可 | https://github.com/jacob-bd/the-ai-counsel |

1. 从发布页下载Windows x64安装包和教程，核对发布标签review-v11.2。可选地在PowerShell运行 Get-FileHash “安装包完整路径” -Algorithm SHA256，与同一发布页SHA256SUMS.txt比对。
2. 源码使用Python 3.12、uv和Node.js 22这一组已用于检查的环境。先克隆仓库，再在项目根目录运行 uv sync --frozen；进入frontend运行 npm ci 和 npm run build，然后回到项目根目录。
3. Windows下双击“启动审稿网页版.cmd”，或在项目根目录运行 .venv\Scripts\python.exe desktop\server.py --port 3340。已有安装版服务时先停止，避免端口冲突。
4. 如需自己打包，参考仓库desktop/package_windows.py与AICounselServer.spec，使用干净前端产物和独立冻结目录，不把data、.env、个人密钥和稿件放进载荷。
5. 本教程反映v11.2的实际按钮与行为。第三方模型软件可能更新，服务地址、模型下载与鉴权方式以它们自己的官方文档为准。

> 版本发布同步源码和安装文件，不提供云端托管或额外账号。安装包中“详细教程”与启动器中的教程入口可离线阅读；模型服务是否需要联网，取决于你的实际配置。
