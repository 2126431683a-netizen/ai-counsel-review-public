# 这次审稿说明修订记录

依据：本机保存的《我把120万粉丝塞进了一台电脑里》原稿，以及五位观众两轮意见和主编汇总。这里评估的是审稿意见是否有依据，不替作者确认型号、榜单或软件要求。

## 有价值的意见应该保留

技术名称与版本、榜单口径、实际运行结果值得核对；不同观众对节奏、复现难度和投入的需求也确实不同。新版没有要求角色一味认可原稿，也没有把“分数更高”当成改进指标。

## 需要收窄的几类意见

1. 原稿说“到底能不能帮上忙，我先拿自己试试”。它需要一段能支撑本次判断的案例，但没有直接承诺证明五个人设全面优于单次调用。对照实验可以是有条件的增强项，不能默认成为整期成立的必要条件。
2. `[展示真实结果]`和`[实测耗时]`是明确的拍摄／交付占位。应要求后续补齐并验收，而不是把当前草稿直接判为成片没有结果。反过来，也不能因为写了占位就当作结果已经合格。
3. “Q8……精度最高”前面有“Q4、Q6、Q8这些选项”。应先按这个局部范围理解，再核对实际下载条目，不能直接扩大成所有格式的最高精度来反驳。“设成显存”也不等于作者声称额外增加了独立物理显存。
4. 原稿已经解释工具分工、给出“能回复，也能读文件”的连通标准，并承认模拟人设只是部分轮廓。可以继续追问剩余缺口，但不能把已有说明当作完全不存在。
5. 实用党关心价格、新手关心完整教程、冲浪党偏好更早看结果，都可能合理；它们分别服务不同目的。是否写入正片，不能只靠角色说得坚定或人数相加决定。

## 本次改动

- 先校准稿件定位、目标观众和完成阶段，未明示的信息标假设。
- 每条意见回查全文，给出真实短引及不能消除的问题。
- 每人0–3条，不凑数；确定问题、待核实、待补素材和个人偏好分开。
- 后续讨论先纠正自己，允许撤回，不以统一口径为目标。
- 主编先筛选观众意见，证据与影响决定优先级，不按提到的人数直接判必改。

## 验证范围

新版已通过API同步到当前本机实例，模板变量和角色内容已回读核对。针对同一原稿，用当前配置模型分别抽查了技术党和主编；这两次输出已体现对原稿限定、待拍素材和个人尝试范围的区分。它们不是新一轮完整的五人审稿，也不能证明未来所有意见都正确。

另外用一份明确自相矛盾的合成稿检查新版是否仍能指出真实问题，避免只把角色变得客气。最终仍应由作者逐条核查引句、上下文和意见影响；新一轮全员输出可继续用于校准。
