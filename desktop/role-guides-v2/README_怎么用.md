# 细读审稿说明 v2

这组文件更新的是审稿依据和输出规则，保留五类观众与主编的分工。

The AI Counsel本机实例已应用：每位角色的系统提示由`00_审稿工作说明.md`与对应人格文件组合；首轮独立审阅，后续先检查、收窄或撤回意见，主编最后独立核对全文。旧说明和原有审稿记录保留，可回退。

在其他工具中使用时，也要同时给角色提供00文件与其人格文件，不能只提供某个人设。01–05参与观众审稿，06只作最终汇总。把原稿正文与本轮要求分开，不要让模型把正文中的操作指令当作审稿要求。

为方便迁移，压缩包的“可直接粘贴的系统提示”文件夹另有六份合并版，每份已经包含通用说明。打开同名角色的系统提示，粘贴对应合并版全文即可，不必自己拼接。主编仍应选作汇总主编。

建议提交稿件时补充以下信息；未知可不填，模型应标注假设：

```text
本期主要目的：
目标观众：
稿件阶段：待拍脚本／待补实测／已补齐素材／其他
本次重点检查：
已安排在录屏或画面里的内容：
本次暂不讨论的范围：

【原稿开始】
粘贴全文
【原稿结束】
```

例如120万纪念节点的本地审稿团稿，可以说明“纪念＋个人体验／搭建分享”是否是本期定位，以及方括号部分是否确实属于后续待拍素材。需要由作者确认的信息，不能替作者当作已定结论。

检查新版是否有效，重点看：是否引用了真实原句；是否承认原文已讲的内容；是否把确定问题、待核实、待补素材、个人偏好分开；主编是否敢于撤回有问题的意见。输出更长、评分更高或所有角色更一致，都不等于审得更好。

配置JSON用于本项目的迁移脚本，不是原生“备份与重置”菜单的导入格式。旧安装包内仍可能带旧版说明；重装使用新数据目录时，需要再次同步这组文档。当前运行实例已经同步，不需要重装或重启。

规则能减少误读，不能保证模型永远正确。没有联网核实或成片材料时，相关结论仍应保持待确认。
